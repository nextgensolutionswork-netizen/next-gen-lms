## Database compatibility and migration recommendation

**Do not apply the pending migration as-is.** Live schema already includes the November 2 country/WhatsApp columns and YouTube/Offline lead constraint. November 3 deduplication columns/indexes are absent. Its proposed global canonical-phone unique index lacks tenant scope; idempotency_key has only a nonunique index; the international backfill can prepend a country code already present in phone; existing duplicate groups require investigation before uniqueness can be installed.

Required proposals: (1) verified tenant ownership and tenant-aware leads/followups relationships and restrictive policies; stop backfill if ownership cannot be established; (2) canonical normalization and tenant-scoped deduplication/idempotency guarantees, with a reviewed historical duplicate plan; (3) durable admission-to-lead relationship/source attribution; (4) explicit training-mode compatibility and, only if intended, separate admission WhatsApp fields. Validate each in accessible isolated staging before requesting production approval. No migration was changed or executed during this audit.
